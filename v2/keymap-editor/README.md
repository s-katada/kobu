# kobu2 keymap editor

kobu2（v2）のキーマップとトラックボール設定を、ブラウザから直接編集する SPA です。
実機の見た目そのままの盤面を出し、**変えたいキーをクリックして選ぶ**だけで割り当てを
変更できます。

- 公開先: `https://kobu-editor.digletts.dev/v2/`（v1 と同じ Worker の `/v2` 配下）
- 対象: **kobu2 のみ**（USB PID `0x425A` / set 2 の `0x425B`）。初代 kobu はキー配列が違うので
  [`../../v1/web/rmk-editor`](../../v1/web/rmk-editor) を使ってください。
- 必要環境: WebHID が使えるデスクトップブラウザ（Chrome / Edge など Chromium 系）

![kobu2 実機](docs/kobu2-reference.jpg)

## できること

| 機能 | 内容 |
|---|---|
| キーマップ編集 | 7 レイヤー × 40 キー。盤面のキーをクリック → 検索・カテゴリ・実キー入力から選択 |
| 動作の装飾 | 修飾つき (WM) / 長押しで修飾 (MT) / 長押しでレイヤー (LT) / レイヤー操作 (MO・TG・TO・OSL・DF) |
| チューニング | カーソル速度 (CPI 倍率)、スクロール間隔・反転、ステータス LED のしきい値。**その場で実機に反映** |
| バッテリー表示 | 左右それぞれの残量（30 秒ごとに自動更新） |
| 通電テスト | 全 40 キーを 1 つずつ押して、スイッチが MCU まで届いているか確かめます（組み立て後の導通確認） |
| デモ表示 | 実機が無くても盤面と操作感を確認できます |

キーマップの変更はいったん手元に溜まり、**「キーボードに書き込む」** で一括送信します。
ロック解除の操作は要りません — Vial の作法では書き込み前に解除しますが、rmk 0.8.2 が
ロックでゲートしているのは通電テストが読む `SwitchMatrixState` の 1 箇所だけで
（`host/via/mod.rs:140`、クレート中で `is_unlocked()` を参照している唯一の場所）、
`DynamicKeymapSetKeyCode` は素通りします。

### 通電テスト

「通電テスト」タブは、**キーマップを通す前のスイッチの状態**を実機から読み出します。押した
キーが緑になり、最後まで緑にならないキーはスイッチ・ソケット・FFC・XIAO のピンのどこかで
導通していません（キーマップの問題ではありません）。列や行がまとまって残った場合はその旨を
表示するので、当たりを付けてテスターを当てられます。

読んでいるのは Via の `GetKeyboardValue / SwitchMatrixState (0x02 / 0x03)` で、ファームウェア
側は `matrix_state`（rmk がキーマップ参照より前に更新するビットマップ）をそのまま返します。
つまり**レイヤーキーや割り当ての無いキーも反応します**。実装は `src/protocol/matrix.ts` と
`src/state/matrixTest.ts`。

知っておくべき挙動が 3 つあります。

* **開始時に一度ロック解除が必要です。** ファームウェアはロック中だとビットマップを書かず、
  「どのキーも押されていない」と区別の付かない返事（要求のエコー＝全ゼロ）を返します。そのため
  開始ボタンを押すと解除操作（左右いちばん外側の小指キー 2 つを同時押し）を求めます。解除状態は
  電源を入れ直すまで続きます。解除キーは左右に 1 つずつなので、**右半分の電源が入っていないと
  解除自体ができません**。
  ⚠ この 2 バイト目の極性は間違えても静かに壊れます（ロック中の 0 を「解除済み」と読むと、
  チョードを要求しないまま全ゼロを読み続け、「入力はできるのに 1 つも反応しない」画面になる）。
  `src/protocol/unlock.test.ts` がファーム側の実装と突き合わせて固定しています。
* **右半分は左半分と BLE でつながっている必要があります。** ビットマップはセントラル（左）
  にあり、右のキーはペリフェラルが転送したイベントで更新されます。右の電源スイッチが
  入っていないと、右のキーは 1 つも反応しません。
* **テスト中の打鍵はページ側で握り潰します**（Esc で終了）。ただしブラウザ自体のショート
  カット（⌘W など）は JavaScript からは止められません。

ファームウェアの変更は不要です。この機能が使う `vial_lock` は rmk の既定 feature で、
`v2/firmware/rmk/Cargo.toml` はそれを無効にしていないため、現行の UF2 がそのまま応答します。

## 開発

Node / pnpm はリポジトリルートの flake が固定しています。

```sh
cd v2/keymap-editor         # direnv がルートの devshell (Node + pnpm) を起動
pnpm install
pnpm dev                    # http://localhost:5173
pnpm test                   # vitest
pnpm lint                   # biome
pnpm typecheck
pnpm build                  # dist/
```

デプロイ用のビルドだけ `--base=/v2/` を付けます（`.github/workflows/web.yml` 参照）。
ローカルの `pnpm dev` / `pnpm build` は `/` のままです。

## 構成

| ディレクトリ | 中身 |
|---|---|
| `src/transport/` | WebHID による Vial パケット送受信。v1 エディタから流用（PID だけ kobu2 に限定） |
| `src/protocol/` | Via / Vial コマンド、ハンドシェイク、キーマップ、キーコード辞書、Custom Value。v1 から流用（`matrix.ts` だけ v2 で追加） |
| `src/board/` | **v2 固有**。実基板 CAD から起こしたジオメトリと、盤面 SVG |
| `src/state/` | zustand ストア（接続 / キーマップ / チューニング / 通電テスト） |
| `src/components/` | UI |

### 盤面ジオメトリについて

`src/board/geometry.ts` は**すべて実測値**で、目分量で描いた形は入っていません。

| 要素 | 出所 |
|---|---|
| スイッチ位置・回転 | `v2/pcb/left-main`, `v2/pcb/thumb-left` の KiCad |
| ケース外形（メイン / 親指） | `v2/case/{main,thumb}-top-plate.stl` を z=0.5 でスライス |
| トラックボール筐体・XIAO 蓋・ヒンジ | `v2/case/*.stl` の実寸 |
| キーキャップの大きさ | 実機写真（プレートの 14mm 開口を定規に実測） |

v2 の基板はスイッチが **B.Cu 側**にあるため、KiCad の標準表示は物理的な上面視と左右反転して
います（コード内に変換式を記載）。

ケース部品は**平行移動だけ**でこの座標系に乗り、しかも位置合わせは推定ではなく**証明済み**です。
印刷されたトッププレートをスライスするとスイッチごとに 14.00×14.00mm の開口が現れ、その中心
20 個すべてが KiCad のスイッチ中心と **0.00mm で一致**します。トラックボール筐体も整合しており、
中心は PMW3610 のパッドから 0.3mm しかずれません。

**唯一の推定値**がメインユニットと親指ユニットの相対位置です。両者は別 KiCad プロジェクトで
原点が無関係なため、ここだけ上の実機写真に合わせ込んでいます（誤差 2mm 程度）。
右半分は左半分の剛体鏡像として生成しています。

プレート外形にはネジ座の逃げ（縁に食い込んだ浅い円弧）が入っていますが、組み上げた状態では
その外側をサイドプレートが通るため見えません。そこで**円弧状の小さな凹みだけ**を埋めています
（4 セグメント以上・9mm 未満・18mm² 未満）。実際の段差は 2〜3 本の直線なので、大きさではなく
形で区別され、列スタッガーは残ります。

この位置合わせが将来ずれないよう、3 つのテストで固定してあります。①全キーがキャップ四隅まで
プレート多角形の内側にあること ②メインプレートが最外キャップから四辺すべて 3.15mm の余白を
持つこと（1mm ずれると余白が揃わなくなる） ③親指プレートの後端が最外キーの中心から
12.65mm 後ろにあること。

### チューニング値の永続性

チューニングの各項目は Via Custom Channel `0xC0` 経由でファームの atomic を直接書き換えます。
**ファームは保存しないため、電源を入れ直すと既定値に戻ります**
（`v2/firmware/rmk/src/config.rs` の "Persistence" を参照）。恒久的に変えたい場合は
`keyboard.toml` を編集して焼き直してください。

また 7 項目のうち「縦スクロール反転」と「LED 紫の保持時間」は、現在のファームに読み取り側が
無いため動作に影響しません。UI 上でも無効表示にしてあります。
